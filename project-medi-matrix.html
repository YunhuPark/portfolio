Core question
의료 AI 데모를 만들 때, 모델보다 먼저 지켜야 할 데이터 경계는 무엇인가?
Live Demo / 01

합성 의료영상을 실제 3D Viewer에서 확인합니다.

합성 NIfTI 입력을 검증한 뒤 Mesh로 변환해 브라우저에서 시각화합니다. 아래 화면은 공개 데모에서 1단계 의료영상 업로드가 완료된 실제 상태입니다.

Problem

의료 파일은 일반 이미지처럼 다룰 수 없습니다.

NIfTI와 NumPy 의료영상은 다차원 배열이므로 파일 형식, 차원, 값 범위와 크기를 잘못 처리하면 서버 자원과 보안에 영향을 줄 수 있습니다. 초기 코드의 비밀값 관리, 위험한 pickle 로딩, 입력값 검증 부족과 문서·구현 불일치를 운영 경계 관점에서 다시 정리했습니다.

My role

모델 데모와 운영 경계를 분리했습니다.

  • NIfTI·NumPy 파싱과 GLB Mesh 변환 흐름 정리
  • 파일 크기·dtype·차원·NaN/Inf 검증과 임시파일 정리
  • JWT 인증, Private Storage와 사용자별 경로 격리 설계
  • Vitals WebSocket replay와 Demo/Model inference mode 분리
  • Golden-Time으로 민감정보 없이 합성 데모 분석 컨텍스트를 전달하는 browser handoff 구현
Decision

업로드 파일과 공개 URL을 신뢰하지 않았습니다.

Safe parsing

allow_pickle=False를 적용하고 object dtype, 비정상 차원, NaN·Inf 및 과도한 파일 크기를 차단했습니다.

Private storage

생성된 Mesh와 Vitals 파일을 사용자 경로로 격리하고, 인증된 사용자에게만 만료형 Signed URL을 발급하도록 설계했습니다.

Explicit inference boundary

공개 배포는 합성 데이터 기반 Demo Inference로 두고, 실제 모델 추론은 별도 의존성과 자원 조건을 요구하도록 분리했습니다.

Minimal context handoff

후속 병원 탐색에는 응급도·모달리티·병변 규모·필요 진료 역량 같은 데모 컨텍스트만 전달하고 JWT, patientId, meshId, Signed URL과 토큰은 URL에서 제외했습니다.

System Flow

영상 입력과 Vitals를 하나의 멀티모달 흐름으로 연결했습니다.

의료영상만 렌더링하는 데서 끝내지 않고 합성 Vitals CSV를 두 번째 입력으로 연결하고, WebSocket replay를 통해 생체신호와 데모 위험 점수를 같은 화면에서 모니터링합니다.

Decision / Triage

위험 점수를 명시적인 Triage 상태로 변환합니다.

합성 데이터 기반 위험 점수는 진단명이 아니라 데모용 의사결정 입력입니다. 포트폴리오에서는 최종 RED 상태와 위험 점수가 동시에 확인되는 화면을 사용해 모델 출력과 행동 상태의 경계를 보여줍니다.

Model → System → Action

모델 연구에서 시스템, 그리고 행동 지원까지 연결했습니다.

세 결과물은 같은 의료 AI 문제의 연속선에 있지만 역할은 다릅니다. 연구 결과, 현재 프로토타입, 독립 제품의 경계를 유지하면서 실제 구현된 연결만 표시합니다.

Golden-Time

독립 응급의료 탐색 서비스로, Medi-Matrix의 합성 데모 분석 컨텍스트를 받아 병원 추천 컨텍스트와 필터에 반영합니다.

Live product ↗
현재 구현 관계. IMST-Mamba는 독립 연구 프로젝트이며 공개 Medi-Matrix는 실제 학습 모델이 아닌 Demo Inference를 사용합니다. Medi-Matrix → Golden-Time은 브라우저 URL handoff로 구현되어 있으며 triage, modality, lesion volume, capabilities 등 최소 합성 데모 컨텍스트만 전달합니다. JWT·patientId·meshId·Signed URL·access token은 전달하지 않습니다. 이는 서버 간 자동 진료 의뢰나 임상적으로 검증된 통합 시스템을 의미하지 않습니다.
