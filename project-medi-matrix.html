Core question
의료 AI 데모를 만들 때, 모델보다 먼저 지켜야 할 데이터 경계는 무엇인가?
Problem

의료 파일은 일반 이미지처럼 다룰 수 없습니다.

NIfTI와 NumPy 의료영상은 다차원 배열이므로 파일 형식, 차원, 값 범위와 크기를 잘못 처리하면 서버 자원과 보안에 영향을 줄 수 있습니다. 기존 코드에는 추적된 환경 변수 파일, 위험한 pickle 로딩, 입력값 검증 부족과 문서·구현 불일치가 있었습니다.

My role

모델 데모와 운영 경계를 분리했습니다.

  • NIfTI·NumPy 파싱과 GLB Mesh 변환 흐름 정리
  • 파일 크기·dtype·차원·NaN/Inf 검증과 임시파일 정리
  • JWT 인증, Private Storage와 사용자별 경로 격리 설계
  • Vitals WebSocket replay와 Demo/Model inference mode 분리
Decision

업로드 파일과 공개 URL을 신뢰하지 않았습니다.

Safe parsing

`allow_pickle=False`를 적용하고 object dtype, 비정상 차원, NaN·Inf 및 과도한 파일 크기를 차단했습니다.

Private storage

생성된 Mesh와 Vitals 파일을 사용자 경로로 격리하고, 인증된 사용자에게만 만료형 Signed URL을 발급하도록 설계했습니다.

Explicit inference boundary

공개 배포는 합성 데이터 기반 Demo Inference로 두고, 실제 모델 추론은 별도 의존성과 자원 조건을 요구하도록 분리했습니다.

System

3D 영상과 시계열 데이터를 안전한 처리 흐름으로 연결했습니다.
