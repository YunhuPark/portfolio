MEDI-
MATRIX

의료영상과 Vitals를 하나의 Case Context로 정리하고, 실제 학습된 Vitals AI 신호에서 필요한 의료자원을 구조화해 Golden-Time의 병원 후보 탐색까지 연결한 비임상 의사결정 지원 프로토타입입니다.

TYPEPersonal Prototype
ROLEArchitecture · Backend · Security
STATUSVision demo / Vitals model
STACKFastAPI · React · PyTorch · Three.js · Supabase
Core question
영상·Vitals AI 신호를 어떻게 안전한 전원 후보 탐색으로 연결할 것인가?
Problem

중증환자 전원에는 모델 점수만으로 부족합니다.

의료영상, 생체신호, 병원 수용 자원은 서로 다른 시스템과 형식에 흩어져 있습니다. Medi-Matrix는 이를 하나의 Case Context로 묶고 AI Risk를 해석 가능한 근거와 전원 자원 조건으로 변환한 뒤, 실제 공개 응급의료 자원 탐색으로 이어지는 흐름을 구현했습니다.

System flow

Imaging + Vitals → AI Risk → Required Resources → Hospital Candidates

Vitals AI

PhysioNet 2019 실제 ICU 시계열로 Causal GRU를 학습했습니다.

HR, SBP, DBP, Resp, Temp, SpO2와 관측 여부·recency·시간 특성을 결합한 19개 feature를 사용하고, 공식 SepsisLabel을 대상으로 patient-level stratified split에서 평가했습니다.

0.7946Held-out test AUROC
0.3451Challenge Utility
0.0950AUPRC
0.5996Validation-selected threshold
Logistic Regression, Temporal XGBoost, Causal GRU, compact IMST-Mamba를 동일한 여섯 Vitals 조건에서 비교했고, 서비스 통합 후보는 Challenge Utility와 AUROC가 가장 높았던 GRU로 선택했습니다. 이 결과는 비임상 연구용이며 진단 성능을 의미하지 않습니다.
Inference boundary

Vision과 Vitals의 검증 수준을 같은 것으로 표현하지 않습니다.

Vision

공개 Vision 입력과 결과는 합성 데이터 기반 synthetic/deterministic demo입니다. 실제 임상 segmentation 성능을 주장하지 않습니다.

Vitals

공개 배포는 VITALS_INFERENCE_MODE=model에서 체크섬으로 검증된 vitals_gru_challenge2019_v1 PyTorch 모델을 로드하고 실제 추론합니다. model provenance와 clinical_use=false를 WebSocket payload와 UI에 전달합니다.

Grounded transfer support

AI score를 자유 생성 문장이 아니라 구조화된 행동 지원 정보로 바꿨습니다.

Grounded AI Transfer Brief는 현재 GRU probability, model ID, validation threshold, inference provenance를 결정론적으로 연결합니다. 이어서 Triage와 modality를 바탕으로 ICU, CT/MRI, neurosurgery, neurology 같은 필요한 의료자원을 구조화합니다.

LLM이 임의로 진단을 만들어내는 구조가 아닙니다. below-threshold 역시 “안정”이나 “전원 불필요”로 해석하지 않도록 경계를 명시했습니다.
Golden-Time handoff

transfer_resources_v1로 자원 기반 후보 탐색까지 연결했습니다.

Medi-Matrix는 allowlisted capabilities와 specialties를 Golden-Time으로 전달합니다. Golden-Time은 E-Gen 기반 병원 자원 정보의 응급실 병상, ICU, CT/MRI, 진료과 적합성을 후보 탐색과 랭킹에 반영합니다.

PASSES

triage · resourceContract · capabilities · specialties · nonclinical markers

EXCLUDES

JWT · access token · patient ID · mesh ID · Signed URL

Candidate search, not automatic transfer. 이 연결은 자동 최적 병원 결정이나 임상 전원 지시가 아니라 공개 의료자원을 이용한 후보 탐색/우선순위 지원입니다.
Production E2E

배포 환경에서 모델 provenance부터 Golden-Time 수신까지 검증했습니다.

Sample Case → authenticated demo bootstrap→ WebSocket → real Vitals GRU provenance→ AI Risk UI → Grounded Transfer Brief→ structured transfer resources→ Golden-Time popup → transfer context receipt
Production smoke는 inference_mode=model, model_id=vitals_gru_challenge2019_v1, clinical_use=false, resourceContract=transfer_resources_v1을 검증합니다. 라이브 병원 카드 하나의 실제 자원 일치까지 고정 assertion한 것은 아니며 해당 resource-fit 로직은 Golden-Time 테스트에서 별도 검증합니다.
Security

의료 파일과 결과 URL을 신뢰하지 않았습니다.

  • 50MB 업로드 상한, allow_pickle=False, object dtype·비정상 차원·NaN/Inf 차단
  • Supabase Auth JWT와 Private Storage, 사용자별 파일 경로 격리
  • 만료형 Signed URL을 통한 결과 접근
  • 익명 공모전 Demo Session도 정식 JWT를 사용하고 인증/격리를 우회하지 않음
  • Golden-Time handoff에 인증·식별·스토리지 민감값을 전달하지 않음
Model → System → Action

관련 연구와 현재 시스템, 독립 제품의 경계를 분리했습니다.
